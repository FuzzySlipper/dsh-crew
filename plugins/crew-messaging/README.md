# dsh-crew-messaging

`dsh-crew-messaging` is an out-of-tree DSH bundle that maps explicitly selected root sessions to local crew-messaging fabric addresses. It makes no change to DSH or the fabric service.

Each configured binding is `{ address, sessionId }`. The adapter treats `sessionId` as its opaque fabric `target_ref`; the fabric does not parse it. Explicit configuration remains authoritative, but root sessions with an explicit user rename also become dynamic addresses: rename a root to `B` and its fabric address is `B`. The adapter calls DSH's public `foldSessionTitle()` and accepts only its `source.kind === 'user'` result, so automatic titles and durable subagents are excluded. Dynamic aliases compare case-insensitively; duplicate titles such as `B` and `b` are deliberately unroutable until the collision is resolved. A currently bound alias belonging to another adapter is likewise left unavailable; a configured collision instead remains a loud operator error. A rename or disappeared root retires the adapter-owned old binding with revision fencing, while unrelated or stale fabric rows are left alone. Discovery reads both live roots and cold persisted roots; a failed catalog scan retains the previous dynamic map. This first adapter intentionally permits exactly one address per root and one root per address; duplicate configured `address` or `sessionId` configuration fails at construction. Only explicitly configured roots currently receive the scoped `crew_addresses` and `crew_message` tools. The send tool derives the sender address from its calling Agent and uses `${sessionId}:${callId}` for fabric idempotency. A reply optionally carries the exact `reply_to_message_id`.

Bound roots receive `crew_addresses`, `crew_directory`, and `crew_message`. The directory contains only `{ address, status, source }`: `status` is `routable`, `ambiguous`, or `conflict`, and `source` is `configured` or `session-title`. It never exposes session ids or fabric target refs. Tool effects track the effective binding map: a discovered title adds tools to a live root, a rename updates its self-address, and an ambiguity or conflict removes sender tools until the root is routable again. `CrewMessagingService.directory()`, `status()`, and `onDirectoryChanged()` are the same model-safe read/refresh face for a dashboard.

Delivery is per-address serialized. The adapter resolves the exact root before it starts fabric dispatch; an unavailable cold target releases the claim because no native insertion was attempted. Before `followup()` it then starts fabric dispatch with a stable native attempt ref, flushes the DSH session, confirms the immutable `crew-messaging` source identity in `user/message` or durable `next-turn` inbox data, and acknowledges. `followup()` is the sole wake mapping: busy Agents receive queued next-turn work without steer, cancel, or injection. A cold target is inspected, rejects known durable subagent sessions, then resumes once per SessionId. The plugin retains and disposes only handles it created; publisher races adopt the winning root. For a cold root, the adapter asks the optional public Session Query service for an observation and reads the authoritative `agentPreset` projection. Cold resume remains queued when Session Query is unavailable or the observation does not include that projection; a discovered preset is mounted through the public `agentPresets` service when it is composed.

Every delivered model message starts with a compact JSON header containing `message_id`, `from`, `to`, `kind` (`ordinary` or `reply`), and `reply_to_message_id` for replies. An ordinary frame explains how to send a linked reply when one is warranted. A reply frame explicitly acknowledges prior work and says not to reply merely because it is a reply; only an independently actionable body should cause a new ordinary message. The body is separately delimited as a JSON string. The frame contains fabric aliases only—never a DSH session id, target ref, lease, or delivery id—and its structured body keeps marker-like message content from being interpreted as delivery metadata. The native source record is unchanged and remains the acceptance proof.

On restart the adapter inspects its own dispatching deliveries. A proven native identity is flushed and acknowledged; anything not provable is terminalized as `outcome_unknown`, never blindly redelivered. Lease tokens remain internal and are not exposed by the service or tools.

## Local current-source use

From the `dsh-crew` repository root, use the system checkout's installed toolchain. Override `DSH_SOURCE_DIR` on boxes that keep DSH elsewhere:

```sh
DSH_SOURCE_DIR="${DSH_SOURCE_DIR:-/home/system/dsh}"
pnpm --dir "$DSH_SOURCE_DIR" exec tsc --noEmit -p /home/dev/dsh-crew/plugins/crew-messaging/tsconfig.json
pnpm --dir "$DSH_SOURCE_DIR" exec vitest run --config /home/dev/dsh-crew/plugins/crew-messaging/vitest.config.ts
pnpm --dir "$DSH_SOURCE_DIR" exec tsc -p /home/dev/dsh-crew/plugins/crew-messaging/tsconfig.client.json
pnpm --dir "$DSH_SOURCE_DIR" exec tsdown --config /home/dev/dsh-crew/plugins/crew-messaging/tsdown.config.ts --tsconfig /home/dev/dsh-crew/plugins/crew-messaging/tsconfig.json
```

Build the local bundle, then add it to the DSH web profile with the setup guide's explicit `file:` package spec. `dsh plugin add` reads and applies the bundle's `cordis.patch.yml`; do not apply that patch separately. The `file:` install keeps runtime peer resolution inside the profile's DSH-managed module fallback; do not substitute `link:` for the live service. The patch defaults to `http://127.0.0.1:8787`, `dsh-crew-messaging`, and one stable trusted-box instance id. Set `DSH_CREW_MESSAGING_URL`, `DSH_CREW_MESSAGING_ADAPTER_ID`, `DSH_CREW_MESSAGING_INSTANCE_ID`, and `DSH_CREW_MESSAGING_BINDINGS` (a JSON array) in the web service environment as described in [the agent-box setup](docs/agent-box-setup.md). Deployment tuning is explicit in the provider config: `leaseDuration`, `renewMs`, `pollMs`, `claimDuration`, `ttl`, `acceptanceTimeoutMs`, and `acceptancePollMs`. The bounded acceptance wait covers DSH's brief handoff between removal from the pending inbox and append of the canonical durable user message; it never retries native insertion.

Current limitation: cold recovery rejects sessions whose persisted header is explicitly `origin: 'subagent'`; a non-subagent root with an unavailable persistence backend remains queued in the fabric. The adapter cannot prove model processing or replies—only native DSH acceptance.

## Web cockpit

With the Web profile, the plugin contributes **Settings → Crew messaging**. Its dashboard polls a same-origin Host route for the effective alias directory, local fabric readiness, adapter lifecycle, the most recent 20 messages and deliveries, and the active runtime timings. A timing change still belongs in the profile configuration and takes effect after a DSH service restart. The route projects aliases, message ids, timestamps, states, and bounded message previews only; it never returns DSH session ids, fabric target references, or lease tokens.

The plugin contributes a separate **Settings → Crew review** page when the sibling `crew-review` service is available at `DSH_CREW_REVIEW_URL` (default `http://127.0.0.1:8413`). It shows service/backend state, aggregate capacity, queued, running, and finalizing counts, bounded active job identities, recent verdict metadata, task-affinity expiry, and unresolved job failures. A failure stops being actionable when a newer round for that task is active or has completed; stale and superseded failures remain visible only in recent history. Findings remain in Den. **Refresh status** immediately re-reads the projection; **Release** only asks the service to dispose an idle retained task affinity. The projection and controls never expose Codex worker identifiers, prompts, transcripts, or Den finding details.

See [the agent-box setup](docs/agent-box-setup.md) for the profile, bundle, restart, and real local fabric probe path. The sibling [crew-services runbook](../../../crew-services/docs/agent-box-runbook.md) owns the local binary and SQLite operation path.

## Foreign-session workbench

The same Web bundle also adds **Crew sessions** to the sidebar footer. It opens an additive drawer over DSH's normal session browser: the drawer lists the public sessions that adapters have published to `crew-services`, then shows the selected session's bounded event history and follows its named `session_event` SSE stream. A session advertising `queued-prompt-delivery` also receives a **Queue prompt** form. The form submits an ordinary fabric message through the provider-held lease and a dedicated `dsh/workbench` sender address; the browser never receives a fabric lease or native thread ID. That address is bound when the provider starts with `deliver_when_idle`, so it is a visible return target for Codex's dynamic Crew tools before the first prompt. Replies are receipted into the immutable fabric ledger without waking or inserting work into any DSH session, then shown newest-first in the drawer's **Workbench inbox** with their exact linked-reply message id.

The browser only calls plugin-owned same-origin routes. The plugin host projects the bounded session/history JSON, joins the workbench mailbox to immutable message facts, and proxies the SSE body without buffering, carrying EventSource reconnect cursors and `Last-Event-ID` to the trusted loopback service. Public session fields and generic event data are shown, while adapter keys, lease tokens, targets, and native attempt references are omitted. Each prompt gesture has one stable browser operation ID, so a retry after a local submission failure repeats the same fabric submission rather than adding another message. A missing service, an empty session list, a malformed response, or a reconnecting stream remains an ordinary drawer state rather than a DSH-wide failure.
